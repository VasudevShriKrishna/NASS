# PART C — PRIMARY REASONING AND SARVAM INTEGRATION

## 5. Sarvam-105B must remain the primary reasoning model

Use `sarvam-105b` as the default primary reasoning model, subject to verification of the current official API documentation and account access.

Official documentation:

https://docs.sarvam.ai/api/api-guides-tutorials/chat-completion/overview

Use the model for:

- Understanding the user's full request.
- Distinguishing internal-data requests from external research requests.
- Planning multi-step operations.
- Selecting the appropriate tools.
- Interpreting tool outputs.
- Resolving references and follow-up questions.
- Comparing information from multiple sources.
- Evaluating conflicting evidence.
- Creating structured tool arguments.
- Preparing research summaries.
- Preparing report specifications.
- Synthesizing a final answer grounded in retrieved information.

The model must not be treated as the data source itself.

For live or recent questions, retrieve current source information before answering. For private operational questions, query the authorized internal system. For mixed questions, retrieve both types of evidence and explicitly distinguish them.

Never let the model invent a successful tool call, a current web search, an internal record, a shipment, a purchase order, a citation or a generated file.

## 6. Model-routing hierarchy

Create a configurable, capability-aware model router.

### Priority 1: Sarvam-105B

Primary model for complex reasoning, tool selection, data interpretation, evidence reconciliation and final factual answers.

### Priority 2: Sarvam-105B Conversations

Use the conversational model for suitable conversational or voice-oriented tasks when its verified supported capabilities provide a benefit.

Do not let a conversational rephrasing step alter verified figures, record identifiers, source URLs or decisions.

### Priority 3: Eligible alternative models

Discover and verify any other currently supported and account-enabled models.

Use alternatives only when their endpoint, model ID, capability, permissions and tool-calling support are verified.

Do not assume that a model can call tools or return valid structured output merely because it supports chat completion.

Retain Mistral only as a configured and tested fallback or alternative where appropriate. Do not call every model for every question.

Do not depend on deprecated models.

### Required model-router behaviour

Track:

- Model ID and provider.
- Endpoint and feature compatibility.
- Available tools and supported output formats.
- Timeout and retry status.
- Fallback reason.
- Latency and usage.
- Structured-output validation.
- Actual result status.

Never use a different reasoning model as a substitute for a missing external data source.

If live web search fails, retry the connector when appropriate or clearly disclose the limitation. Never ask another model to invent recent news.

1. Retrieve a relevant source.
2. Check its identity, publication date and relevance.
3. Prefer primary and official sources for authoritative claims.
4. Seek independent corroboration when practical.
5. Flag conflicting, disputed or unsupported claims.
6. Retain the source URL and relevant excerpt or evidence reference.
7. Include publication and retrieval times.
8. Explain whether the evidence supports the complete claim or only part of it.

Use an appropriate evidence hierarchy:

1. Official source documents and authoritative registries.
2. Official government, company, regulator, port and tender-board announcements.
3. Direct supplier, carrier or client publications.
4. Reputable media with identifiable authorship and publication dates.
5. Other sources suitable for discovery but requiring further verification.

Several websites republishing the same release must not automatically count as several independent sources.

Never fabricate citation URLs or claim verification without retrieving evidence.

**Verification notes:** missing evidence, conflicts, uncertainty and limitations.

Do not default to PDF, Excel, JSON or an uploaded-source request when the user asks for an ordinary text answer.
